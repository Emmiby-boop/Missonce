# 小辣椒头像 · 首页改版产品方案

**版本**：v1.0  
**日期**：2026-06-29  
**提出人**：产品通（AI 助手）  
**状态**：待评审

---

## 一、产品现状与核心问题

### 1.1 用户行为数据

| 指标 | 数值 | 说明 |
|------|------|------|
| 头像下载占比 | >90% | 壁纸下载极少，壁纸 Tab 利用率低 |
| 流量来源 | 微信搜索关键词 + 公众号引流 | 用户意图明确：找头像 |
| 内容格式 | 动态头像（GIF）为主打差异化 | 静态资源为辅 |

### 1.2 当前产品问题

| 问题 | 影响 |
|------|------|
| 首页是「工具页」而非「内容页」 | 用户进来第一屏看不到头像内容，跳失率高 |
| 「头像」和「壁纸」两个 Tab 结构重复 | 都是分类+排序+网格，壁纸 Tab 无存在价值 |
| 导航栏 `#07c160` 绿色过强 | 图片内容页视觉噪音大，显得廉价 |
| 首页 section 层次感弱 | 40rpx 绿色短横线 indicator 几乎看不清 |
| 快捷功能区块占用首屏面积过大 | 「小店/灵感/每日/去水印」挤占内容展示空间 |

---

## 二、产品定位刷新

```
旧定位：头像壁纸工具小程序
        ↓
新定位：动态头像发现与下载平台
        ↑
    GIF 是核心差异化
```

**产品设计原则**：
1. **内容优先**：用户进来直接看头像，不是看按钮
2. **GIF 突出**：动态内容天然吸引眼球，要充分利用
3. **搜索友好**：来自搜索的用户，第一屏就要看到相关内容
4. **工具后置**：处理功能（去水印/AI生成）收到独立 Tab，不占首页

## 三、Tab 结构改版方案

### 3.1 改版前后对比

| Tab 序号 | 现在 | 改版后 | 说明 |
|---------|------|--------|------|
| 1 | 首页（工具页） | **发现**（内容流首页） | 小红书风格，直接展示内容 |
| 2 | 头像（分类网格） | **头像**（保留优化） | 分类浏览专用页，两级分类 |
| 3 | 壁纸（没人用） | **AI 工具**（新增） | 去水印 + AI 生成 + 智能抠图 |
| 4 | 我的 | **我的**（保留） | 新增「最近下载」入口 |

### 3.2 「AI 工具」Tab 详细规划

| 功能入口 | 优先级 | 说明 |
|---------|--------|------|
| 去水印 | P0（已有） | 从快捷功能移入，跳转现有小程序 |
| AI 头像生成 | P1 | 用户输入描述，调用 AI API 生成头像 |
| 智能抠图/换背景 | P2 | 上传头像，自动抠图换背景 |
| 尺寸适配 | P2 | 头像裁成微信/抖音/小红书尺寸 |

### 4.1 页面结构（顶部 → 底部）

│  【内容流】双列瀑布流                    │

│  │动图 │  │    │                │

│  ┌────┐  ┌────┐                │

  -webkit-backdrop-filter: blur(12px);
  border-bottom: 0.5px solid rgba(0, 0, 0, 0.06);
  box-shadow: none; /* 去掉原有阴影 */

/* 搜索框内置在导航栏里 */
.nav-search-inline {
  margin: 0 24rpx;

  border-radius: 999rpx;
  height: 64rpx;
  display: flex;
  align-items: center;
  padding: 0 24rpx;
  font-size: 28rpx;
  color: #999;

/* 深色模式 */

  .custom-nav {

### 4.3 分类 Tab 设计

**交互规格**：
- 默认定位在导航栏下方，`position: sticky`

### 4.4 内容流（双列瀑布流）设计

**图片加载策略（已确认正确）**：
- `utils/image.js` 的 `processUrl()` 已正确处理 GIF：只缩放不转 webp ✅
- 静态图：转 webp + 缩放，节省流量
- GIF：只缩放（`thumbnail/${width}x/interlace/1/quality/80`），保持动画 ✅

**卡片结构**：

```xml
<!-- 每个瀑布流卡片 -->
<view class="waterfall-card" bindtap="onCardTap">
  <!-- 图片区（GIF 自动播放） -->
  <image 
    src="{{item.optimizedUrl || item.url}}" 
    mode="widthFix" 
    lazy-load
    class="card-img"
  />
  
  <!-- GIF 角标 -->
  <view class="gif-badge" wx:if="{{item.isGif}}">GIF</view>
  
  <!-- 底部信息层 -->
  <view class="card-info">
    <text class="card-category">{{item.category}}</text>
  </view>
</view>
```

**性能优化策略**：
```
滚动时：
  - 可视区内的 GIF：正常播放
  - 滚出可视区 > 500ms：暂停（image 组件不支持暂停，
    解决方案：滚出时用 <view> 覆盖，只显示第一帧静态图）
```

> ⚠️ **技术限制说明**：微信小程序 `<image>` 组件不支持程序化暂停 GIF。
> 解决方案：用 `wx.createIntersectionObserver` 监听可视状态，
> 滚出时用一张静态封面图（缩略图）替换 GIF URL，滚入时恢复。

## 五、交互流程设计

### 5.1 用户进入首页后的理想路径

```
用户打开小程序
        ↓
  【首页】直接看到头像内容流
        ↓
  滚动浏览（GIF 自动播放吸引眼球）
        ↓
  点击感兴趣的头像 → 进入预览页（支持下载/收藏）
        ↓
  或：点击「动态」分类 → 只看 GIF 头像
        ↓
  或：点击导航栏搜索 → 进入搜索页（承接搜索意图）
```

### 5.2 分类筛选交互

| 交互 | 说明 |
|------|------|
| 点击分类 Tab | 内容流实时筛选，不跳页，无刷新感 |
| 切换分类 | 保留滚动位置，内容流从该位置开始展示新内容 |
| 「推荐」Tab | 默认展示：热门头像（混合静态+GIF）+ 特殊卡片穿插 |

## 六、技术方案要点

### 6.1 数据结构变更

**首页 `sections` 数据**（来自 `getHomeData` 云函数）：

现在的数据结构是按「板块」组织的，改版后需要支持「按分类筛选」：

```javascript
// 建议新增字段
{
  sections: [
    {
      id: 'recommend',
      title: '推荐',
      type: 'waterfall_mixed',  // 新类型：混合静态+GIF
      items: [...],
      // 新增：支持按分类筛选
      filterable: true,  
      categories: ['动漫', '情侣', '男生', '女生', ...]
    }
  ],
  categories: ['推荐', '动态', '动漫', '情侣', '男生', '女生', '可爱']
}
```

### 6.2 性能保障

| 问题 | 方案 |
|------|------|
| GIF 自动播放耗流量 | 只加载可视区 GIF，非可视区用静态封面图 |
| 瀑布流图片高度计算 | 提前在云函数里计算并存储 `imageHeight` 字段 |
| 分类切换闪烁 | 预加载下一个分类的前 6 条数据 |

## 九、风险与应对

| 风险 | 应对 |
|------|------|
| GIF 自动播放导致流量消耗大 | 可视区外暂停策略 + 用户设置里加「省流模式」开关 |
| 瀑布流性能问题（低端机） | 分页加载，每页 20 条，滚动到底再加载下一页 |
| 分类 Tab 过多，用户找不到 | 「推荐」和「动态」固定在前两位，其余可横滑 |
