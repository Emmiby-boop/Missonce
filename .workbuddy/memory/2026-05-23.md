### adminAuth 云函数根因修复 ✅

**根因定位**：
- `index.js` 第3行 `const CryptoJS = require('crypto-js')` 引用了 crypto-js
- 但 `package.json` 的 dependencies 中只有 `bcryptjs` 和 `wx-server-sdk`
- **缺少 `crypto-js` 声明导致云函数运行时崩溃**：`FUNCTIONS_EXECUTE_FAIL code exit unexpected`

**修复操作**：
1. `package.json` 添加 `"crypto-js": "^4.2.0"`
2. `npm install` 安装依赖（added 1 package）
3. `tcb fn deploy --force --dir .` **重新部署到云端**
4. 输出：`√ [adminAuth] Cloud function deployed successfully!`

**关键经验**：
- 云函数报 `code exit unexpected` 时，第一反应应检查 **所有 `require()` 的模块是否都在 package.json 中声明**
- 即使本地 node_modules 有该包，云端部署时只按 package.json 安装依赖

### 小程序重复下载修复 ✅

**任务**：修复用户重复下载行为（下载记录中出现大量重复数据）

**根因分析（4 个问题点）**：

| # | 问题 | 文件 | 严重度 |
|---|------|------|--------|
| 1 | `addDownloadRecord()` 本地无去重，每次直接 push | wallpaper-preview.js + preview.js | 🔴 高 |
| 2 | `recordDownload()` 云端直接 `.add()`，无去重检查 | api.js | 🔴 高 |
| 3 | `downloadImage()` 无防重复点击保护 | wallpaper-preview.js + preview.js | 🟡 中 |
| 4 | `saveToAlbum` 授权失败回调递归调用 `downloadImage()`（重走广告/积分流程） | wallpaper-preview.js + preview.js | 🟡 中 |

**修复内容**：

1. **本地去重** (`wallpaper-preview.js` + `preview.js` 的 `addDownloadRecord`)：
   - 写入前先按 `url` 过滤已存在的记录，移除旧记录后插入新记录
   - 效果：同一图片多次下载只保留最新一条

2. **云端去重** (`api.js` 的 `recordDownload`)：
   - 改为 `async` 函数，写入前先查询 downloads 集合
   - 查询条件：同一用户(`_openid` 隐含) + 同一 resourceId 或 url + 24小时内
   - 命中则 `return { skipped: true }` 跳过写入和统计更新

3. **防重复点击** (`wallpaper-preview.js` + `preview.js` 的 `downloadImage`)：
   - data 新增 `isDownloading: false` 标志位
   - 入口检查：如果 `isDownloading === true` 直接 return
   - 用 `try/finally` 包裹整个方法体，finally 中延迟 3s 解锁
   - `saveToAlbum` 成功回调中立即解锁（不等 3s）

4. **授权回调修复** (`saveToAlbum` fail 分支)：
   - 授权成功后不再调用 `that.downloadImage()`（会重走广告/积分）
   - 改为重新下载文件 → 调用 `saveToAlbum`（只重试保存步骤）
   - 同时在 fail 回调中添加 `isDownloading = false` 解锁

### 广告组件 Bug 修复 ✅

**任务**：修复广告取消后下载锁死 + 原生广告 SystemError 大量报错

#### 问题 1：广告取消后 isDownloading 锁未释放 ✅
- **根因**：`downloadImage()` 在 `checkLogin()` 失败和 `adResult.success===false` 两条 early return 路径上没有释放 `isDownloading` 锁
- **修复**：在 wallpaper-preview.js 和 preview.js 的两条 return 前添加 `this.setData({ isDownloading: false })`

#### 问题 2：原生广告 SystemError（removeTextView/removeImageView/updateTextView not found）✅
- **根因分析**：
  - `wx:if` 控制显隐 → 销毁/重建 ad-custom 原生节点 → 框架尝试操作已回收节点 → `remove* not found`
  - `hidden` 控制显隐 + 同时 `setData({_pageHidden, showAd})` → 父容器 wx:if 销毁与 hidden 更新子节点同时发生 → `update* not found`
- **wxml 修复方案**（两层防御）：
  - 第1层 `wx:if="{{adUnitId}}"` — 仅当有有效 unit-id 时才渲染 ad-custom（防空 id 报错）
  - 第2层 `hidden="{{!(showAd && position !== 'top')}}"` — 控制显隐切换而不销毁 DOM
- **js hide() 修复方案**（消除竞态）：
  - `hide()` 中 **不再同时** 设置 `_pageHidden` 和 `showAd`，先只设 `_pageHidden: true`
  - 外层 `wx:if="{{!_pageHidden}}"` 销毁父容器时，ad-custom 随之移除，不会触发 hidden 切换
  - 延迟 50ms 后再设置 `showAd: false`（此时 DOM 已销毁完成，仅更新 data 状态）

#### 问题 3：play() interrupted by pause() ✅
- **根因**：`hide()` 中直接调用 `videoAd.destroy()`，destroy 内部先 pause 再释放，与正在进行的 play 竞态
- **修复方案**（分步安全销毁）：
  1. 先保存引用 `const ad = this.videoAd`，立即置空 `this.videoAd = null`
  2. 先调用 `ad.pause()`（同步，让播放器状态机进入 paused）
  3. 延迟 100ms 后再调用 `ad.destroy()`（给状态机足够时间完成转换）

- `components/ad-unit/ad-unit.wxml` — 两层防御渲染策略
- `components/ad-unit/ad-unit.js` — hide() 方法重写（分离 setData 时序 + 分步 videoAd 销毁）
- `subpackages/wallpaper-preview/wallpaper-preview.js` — isDownloading 锁释放
- `subpackages/preview/preview.js` — isDownloading 锁释放

### 顶部广告提前显示 Bug 修复 ✅

**问题**：顶部原生广告（position=top）页面一进来就显示，滑动达到阈值后又重复显示

**根因**：
- wxml 中顶部广告容器的 `wx:if="{{position === 'top' && adUnitId}}"` 只检查了 adUnitId 有值
- `init()` 一旦 `setData({ adUnitId })` 执行 → wx:if 立即满足 → **ad-custom 提前渲染到 DOM**
- 虽然 CSS 有 `opacity: 0` 和 `.show` 类控制可见性，但 ad-custom 原生组件已开始加载
- 滚动到阈值后 `onPageScroll` → `showIfNeeded()` → 又触发一次 showAd=true

**修复方案（最终版，两处修改）**：

**根因**：wxml 中存在 **两个 ad-custom 渲染路径**
1. 第 6-13 行：通用原生广告路径 — 对 position=top 没有排除，hidden 不可靠导致提前显示
2. 第 20 行：顶部悬浮专用路径 — 已加 showAd 守卫

**修复 1**：通用路径增加 `wx:if="{{position !== 'top'}}"` 排除顶部广告
- 顶部广告只走专用的悬浮容器路径，不再经过通用 hidden 路径
- hidden 对 ad-custom 原生组件不可靠（某些基础库仍会渲染/占位）

**修复 2**：顶部悬浮容器 wx:if 增加 `showAd` 条件
- `wx:if="{{position === 'top' && adUnitId && showAd}}"`
- 仅在 onPageScroll 滚动阈值触发后才首次渲染

**修改文件**：`components/ad-unit/ad-unit.wxml`（重构为两条独立渲染路径）
