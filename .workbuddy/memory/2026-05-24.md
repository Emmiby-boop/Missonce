# 2026-05-24 工作日志

## 修复：广告取消后 isDownloading 锁未释放

**问题**：用户点击下载 → 弹出激励广告 → 点击取消 → 再点下载 → 控制台显示"正在下载中，忽略重复点击"

**根因**：`downloadImage()` 中 `isDownloading` 在入口设为 `true`，但以下 early return 路径没有释放锁：
1. `checkLogin()` 未登录时 `return` — 锁未释放
2. `ensureRewardedForFirstDownload()` 返回 `adResult.success === false`（用户取消广告）— 锁未释放
3. 这两个 return 后进入 finally，finally 中有 `setTimeout(..., 3000)` 延迟解锁，导致 3 秒内再点下载被拦截

**修复**：在两个 early return 点添加 `this.setData({ isDownloading: false })` 立即释放锁
- `wallpaper-preview.js` downloadImage() 第1035行（checkLogin）、第1056行（adResult）
- `preview.js` downloadImage() 第988行（checkLogin）、第1008行（adResult）

**涉及文件**：
- `WeChat Mini/subpackages/wallpaper-preview/wallpaper-preview.js`
- `WeChat Mini/subpackages/preview/preview.js`

## 修复：ad-custom 原生广告组件 "removeTextView/removeImageView not found" 大量报错

**错误信息**：
- `SystemError: removeTextView:fail 33409 not found`
- `SystemError: removeImageView:fail 33429 not found`

**根因**：`ad-unit.wxml` 中对 `ad-custom` 原生组件使用 `wx:if="{{showAd && ...}}"` 控制显隐。当 wx:if 从 true→false 时，框架直接销毁 ad-custom 组件及其内部原生 text/image 节点。但微信基础库 3.14.2 的原生渲染层在节点已被底层回收后仍尝试调用 remove → 报 "not found" SystemError。此错误发生在 WAServiceMainContext（框架层），JS 无法 try-catch。

**修复方案**：将 `ad-custom` 的显隐控制从 `wx:if`（销毁/重建）改为 `hidden` 属性（CSS display:none），避免原生节点的突然移除。
- 非顶部广告（middle/bottom）：外层 view 不再用 wx:if 包裹，改在 ad-custom 上用 `hidden="{{!(showAd && adUnitId && ...)}}"`
- 顶部广告：同理，将 `showAd` 条件从 wx:if 移到 hidden 属性
- 顶部容器本身仍用 wx:if 控制（有 adUnitId 才渲染），但内部 ad-custom 用 hidden

**涉及文件**：
- `WeChat Mini/components/ad-unit/ad-unit.wxml` — wxml 模板修改
