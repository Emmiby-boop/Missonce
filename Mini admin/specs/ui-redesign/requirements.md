# 需求文档 — Mini Admin 前端 UI 全面焕新

## 1. 问题陈述（Problem）
当前后台存在**系统性视觉不一致**，导致品牌感弱、维护成本高：
- **双 UI 体系并存**：Naive UI 组件与自研 `.btn-*`/`.card` 类混用，相同功能样式不统一。
- **暗色主题割裂**：Naive `darkThemeOverrides` 用冷蓝灰 `#111827`，而项目 CSS 变量暗色用暖石 `#0c0a09`，两套暗色视觉冲突。
- **字体脱节**：Naive `fontFamily` 设为 `Inter`，与项目字体 Geist/Bricolage 不符。
- **硬编码颜色**：`DashboardPage.vue` 等页面直接使用 `text-green-500`/`bg-blue-500` 等 Tailwind 默认色，偏离品牌绿。
- **`tailwind.config.js` 为空**：无语义色映射，全靠 `text-[var(--text-sub)]` 任意值，难以统一。
- **装饰性动画冗余**：`components/animations/` 16 个组件偏炫技，部分未用，带来性能/一致性风险。

## 2. 范围（Scope）
- **包含**：设计令牌体系（CSS 变量 + Naive overrides）、布局骨架（侧边栏/顶栏）、Dashboard 及高频页面的视觉焕新、核心组件（按钮/卡片/表格/表单/徽标/弹窗）统一、暗色模式对齐、空/加载/错误状态规范。
- **不包含（本期）**：新增业务功能、后端接口改动、路由结构重构（路由内联问题留作后续技术债）。

## 3. 用户故事（User Stories）
- 作为运营，我希望后台视觉统一专业，以便更信任并使用系统。
- 作为管理员，我希望暗色模式下 Naive 弹窗与页面一致，以免割裂感。
- 作为开发者，我希望有一套单一设计令牌，以免再出现硬编码色与双轨样式。

## 4. 验收标准（EARS）
1. 当系统切换明暗主题时，Naive 组件与自研组件的色调、圆角、阴影应**完全一致**（视觉无割裂）。
2. 当用户在任意页面查看时，所有主色调用必须来自 `--primary` 令牌，**不得**出现 `green-500`/`blue-500` 等硬编码 Tailwind 默认色。
3. 当用户使用核心操作（按钮/输入/表格/标签）时，应呈现完整的 Default/Hover/Active/Disabled/Focus 状态。
4. 当页面处于加载/空/错误状态时，应展示设计系统定义的对应占位，而非裸骨架或空白。
5. 当视口宽度 < 1024px 时，侧边栏应可收起且主内容自适应，不出现横向滚动。
6. 当合并令牌体系后，`tailwind.config.js` 应提供语义色映射，业务代码不再使用 `text-[var(--...)]` 任意值写法。

## 5. 非目标（Non-goals）
- 不更换主色品牌（维持微信绿 `#07c160`）。
- 不引入全新组件库，统一收敛到 Naive UI。
- 不做国际化/多语言改造。
